# WalkWar · UI/UX 인수인계

작성 기준: 2026-09-20 / 부산 전체 지도 및 유리 표현 보강 완료 시점

## 1. 먼저 이해할 것

WalkWar는 부산을 걸으며 레이드에 기여하고, 보상으로 배지와 위치 장식을 모으는 모바일 앱의 개발 중인 프로토타입이다. 목표 플랫폼은 iPhone과 Android이며, 웹은 빠르게 화면과 동작을 확인하는 미리보기다.

**지도가 주인공이다. 조작부는 작게 떠 있고, 필요한 정보만 남긴다. 사용자가 더 큰 글씨를 선택하면 가독성을 우선한다.** 이것이 후속 작업의 판단 기준이다.

현재 지도는 부산의 실제 지리 데이터다. 캐릭터 위치, 걸음, 레이드, 랭킹, 포인트와 구매는 체험용이다. 부산 전체를 볼 수 있다고 해서 부산 전역의 실시간 레이드나 위치 서비스가 구현된 것은 아니다.

이 문서는 대화에서 사용자가 확정한 방향과 현재 코드의 구현을 구분해 정리한 것이다. 첨부 참고 이미지의 광고·웹페이지 문구 등은 제품 요구사항으로 취급하지 않는다. 새로운 명시적 사용자 결정이 생기면 이 문서와 DESIGN.md, AGENTS.md를 함께 갱신한다.

## 2. 반드시 유지할 UI/UX 철학

### 지도와 여백

- 화면 전체를 지도로 사용하고 상단 레이드, 지역 선택, 랭킹과 하단 메뉴를 지도 위에 띄운다.
- 지도 중앙을 설명문이나 큰 카드로 채우지 않는다. 설정·상점·수집·지역 목록은 필요한 때 바텀시트로 연다.
- 지도를 끌어보거나 다른 구·군을 선택하는 행위는 캐릭터 이동이나 레이드 기여로 계산하지 않는다.
- 다른 사람의 위치는 표시하지 않는다. 참여자 랭킹은 유지한다.

### 유리는 투명도 이상의 재질

사용자는 일반적인 반투명 블러와 Liquid Glass가 다르다는 점을 직접 지적했다. 상단·하단 조작부에는 배경이 가장자리에서 휘는 굴절, 밝은 반사 테두리, 두께와 배경색이 스며드는 느낌이 필요하다. 단순히 배경 불투명도만 낮춘 결과를 완료로 판단하지 않는다.

실제 Apple 효과, 웹 근사 표현, 다른 플랫폼의 대체 표현을 구분해야 한다. 글자까지 왜곡하거나 유리 효과 때문에 내용을 읽기 어렵게 만들지 않는다. 대비 설정과 기기의 투명도 줄이기가 장식보다 우선한다.

### 작은 외형, 충분한 조작 영역

아이콘과 글자는 작고 간결하게 보이되, 앱의 직접 조작 버튼은 최소 48 × 48 논리 단위의 터치 영역을 확보한다. 컴팩트·기본·크게 중에서 사용자가 선택한다. 글자만 키우지 말고 아이콘과 여백도 같이 바꾼다. 운영체제 글자 확대를 차단하지 않는다.

좁은 화면이나 큰 글씨에서는 랭킹을 간단한 진입 버튼으로 줄이고 별도 화면에서 전체 순위를 보여준다. 필수 정보를 강제로 잘라서 작은 레이아웃에 맞추지 않는다.

### 문구는 선택에 필요한 만큼

설정 화면에는 세 가지 크기, 글자 샘플, 대비 전환만 기본 표시한다. 상점은 상품의 실제 모습, 이름, 가격, 구매 상태를 보여준다. 기능 소개·감성 문구·중복 안내는 기본 화면에 추가하지 않는다.

저장 오류, 지도 로딩 실패, 포인트 부족, 기기 설정 강제 적용처럼 행동에 필요한 안내는 짧게 남긴다. 문구를 모두 없애는 것이 목표가 아니다.

### 장식 상품은 눈으로 이해하게

프레임이나 테마는 상품 카드 안에서 색·테두리·장식 형태가 명확히 보여야 한다. 이름만 표시하거나 긴 설명으로 대신하지 않는다. 현재 전포 네온 프레임은 틸색 이중 링과 두 개의 빛 장식이다. 구매 전 미리보기와 구매 후 지도 마커의 형태가 일치해야 한다.

## 5. 현재 사용자 흐름

1. 실행하면 부산 전체 지도, 부전동 레이드 카드, 지역 선택, 참여자 랭킹, 하단 메뉴가 보인다.
2. 지역 선택에서 부산 전체 또는 16개 구·군으로 이동한다. 드래그·휠·핀치와 +/− 버튼으로 탐색한다. 현재 위치 버튼은 가상 캐릭터 위치로 카메라를 돌린다.
3. 웹에서 WASD 또는 방향키로 가상 캐릭터를 이동한다. 시트나 보상 화면이 열려 있을 때에는 이동을 차단한다. 지도 탐색만으로 HP가 줄어들면 버그다.
4. 이동할 때 체험용 걸음·기여가 증가하고 HP가 감소한다. 보스 처치 시 100 P와 승리 기록을 한 번 받는다.
5. 수집 화면에서 배지를 보고 상점으로 이동할 수 있다. 프레임은 30 P이며, 구매 후 적용 상태와 지도 마커가 바뀐다. 잔액 부족·중복 구매는 막는다.
6. 화면 크기 설정에서 크기·대비를 고르면 즉시 반영하고 기기에 저장한다. 시트를 닫아 지도로 돌아간다.

초기 체험값은 HP 388/720, 0 P, 내부 걸음값 7,000, 승리 0회다. 한 이동당 내부 걸음 8과 HP 감소 8을 사용한다. 이 값들은 프로토타입 동작이며 제품의 최종 보상 정책이 아니다. 지도는 부산 전역을 탐색하지만 키보드 캐릭터 이동은 현재 부전동 주변의 제한된 시뮬레이션 좌표 범위다. 모바일에는 별도의 가상 이동 버튼을 표시하지 않으며 실제 GPS도 아직 연결하지 않았다.

## 7. 실행과 재현

권장 환경은 Node.js 24 LTS와 npm이다. 프로젝트는 Expo SDK 57, React Native 0.86.3, React 19.2.3을 사용한다. 정확한 버전은 package.json과 package-lock.json을 기준으로 한다.

ZIP을 풀고 터미널에서 walkwar-app 폴더로 이동한 뒤 실행한다.

```sh
npm ci
npm run web -- --localhost --port 5195
```

브라우저에서 http://localhost:5195/ 를 연다. 이 주소는 실행한 컴퓨터 안에서만 동작한다. 포트가 사용 중이면 다른 빈 포트로 실행하고 안내된 주소를 사용한다.

휴대폰 확인은 같은 폴더에서 다음 명령을 실행하고 Expo 안내에 따라 호환되는 Expo Go 또는 개발 빌드를 사용한다.

```sh
npm start
```

휴대폰은 개발 서버에 접근 가능한 네트워크가 필요하다. iOS 빌드에는 macOS/Xcode 또는 EAS 환경과 서명이 필요하다. 현재 앱에는 배포용 bundleIdentifier·Android package·서명·스토어 연결이 설정되어 있지 않다. 이 ZIP은 IPA/APK가 아니다.

지도는 MapLibre GL JS 5.24.0을 unpkg.com에서, 스타일·벡터 타일·폰트를 tiles.openfreemap.org에서 읽는다. npm ci만으로 지도까지 오프라인 실행되는 구성은 아니다. 회사 네트워크 차단이나 외부 서비스 장애가 있으면 로딩 실패 화면과 다시 시도를 확인한다. API 키나 실제 위치 권한은 현재 사용하지 않는다.

```sh
npm run typecheck
npm test
npm run export:native
```

마지막 명령은 iOS·Android용 JavaScript/Hermes 번들을 생성한다. 설치·실기기 테스트·스토어 배포를 대신하지 않는다.

## 8. 확인된 것과 남은 일

인수인계 기준 코드에서 TypeScript 검사, 7개 테스트, iOS·Android 번들 생성이 통과했다. 브라우저에서 부산 전체 지도 로딩, 해운대 선택, 확대, 드래그, 내 위치 복귀, WASD 이동, 큰 글자와 대비 전환을 확인했다. 이전 단계에서 가상 구매·적용과 설정 저장도 확인했다.

스크린샷은 이 패키지의 UI 설명을 위한 웹 미리보기다. 네이티브 앱 인증 자료가 아니며, 실행 시 포인트·HP·위치는 체험 진행에 따라 달라질 수 있다.

후속 검증·개발은 다음 순서가 적절하다.

1. iPhone 실기기에서 clear GlassView의 굴절·반사·가독성 및 WebView 지도와의 합성을 확인한다. Android에서도 블러·메모리·스크롤 성능을 확인한다.
2. 세 가지 크기와 OS 큰 글씨, VoiceOver/TalkBack, 투명도 줄이기를 검증한다. 지도 캔버스의 레이블·출처 링크·마커를 포함해 접근성을 보완한다.
3. iOS Safari 및 대상 Android 브라우저에서 웹 유리 효과의 호환성을 확인한다. 지원되지 않는 필터에서 기능이나 가독성이 사라지지 않게 한다.
4. 지도 재로딩·느린 연결·타일 오류·백그라운드 복귀를 확인하고, 필요하면 지도 라이브러리를 로컬 번들로 옮긴다. 외부 지도 출처 표시는 유지한다.
5. 제품 요구가 확정되면 GPS·걸음 측정·서버 레이드·인증·데이터 저장을 연결한다. 권한 흐름과 실제 데이터는 새로 설계·검증해야 한다.

실시간 멀티플레이, 부산 전체 보스 배치, 실제 위치/걸음 측정, 로그인, 서버 저장, 실제 결제, 설치 파일 배포는 아직 구현하지 않았다. 모바일 핀치 조작은 지도 라이브러리로 활성화되어 있지만 실기기 제스처 검증은 남아 있다.

## 9. 변경 완료 판단 기준

- 지도 중앙이 이전보다 불필요하게 가려지지 않는가?
- 추가 문구가 실제 선택이나 오류 해결에 필요한가?
- 컴팩트와 크게에서 글자·카드·터치 영역이 모두 유지되는가?
- 지도 탐색과 캐릭터 이동/기여가 섞이지 않는가?
- 유리 효과를 끈 대비 모드에서도 모든 기능이 보이는가?
- 상품의 실제 적용 모양과 미리보기가 같은가?
- 삭제하기로 한 위젯·타인 위치·긴 안내를 다시 노출하지 않았는가?
- 실제 확인한 플랫폼·동작만 검증 완료로 보고했는가?
