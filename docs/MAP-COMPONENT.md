# AdministrativeMap

`AdministrativeMap` is a native Compose Web-Mercator map for choosing a raid candidate. It exposes the public API in `com.example.myapplication.raid` and keeps the active raid outside the component. The initial camera fits the Korea overview and shows individual 시·도 flags; zooming progressively reveals 시·군·구 and then 읍·면·동 flags and boundaries. Marker visibility uses a screen pixel-density-aware zoom adjustment, so zooming out far enough shows no administrative flags, labels, or boundaries. There is no administrative clustering or cluster chooser. Each visible feature has a compact 48×44dp marker; when markers overlap, the component nudges them into nearby free space (at most 42dp per axis) and draws a thin connector to the actual position. A marker that cannot be placed remains available at a closer zoom. Tapping a marker highlights the actual boundary and calls `onCandidate(region)` for the parent to show history and require an explicit start confirmation. Boundaries themselves do not select a raid.

The parent supplies visible-window `loadAreas(west, south, east, north, level)` responses with at most 100 GeoJSON Polygon or MultiPolygon features. The component debounces each changed viewport by 350 ms; cancellation of its Compose effect prevents stale results from replacing the current view. Pass `refreshKey` (for example the latest defeat id plus mode) after a completed raid to refresh capture flags without changing the camera. A region may include `capture:{defeatedAt,encounterNumber,teams}`; up to three server-provided team flags are shown, otherwise country ISO is converted to a Unicode flag, and uncaptured regions show a white flag.

It renders standard OSM raster tiles only for current visible tiles. Tiles use HTTPS, a stable identifying User-Agent, a local cache with a seven-day minimum lifetime, and no prefetch/offline feature. Memory retains only the current viewport, including when slow tile requests finish after a pan. The visible `© OpenStreetMap contributors` attribution is required by the [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/). Tile or network failure deliberately shows a subdued grid and an explicit status instead of pretending it is geographic data.

`focusRegion` changes recenter only once for each new `id`, so later polling does not fight user pan/zoom. The current-location control centers the camera without changing GPS or virtual character data. GPS participants use their geographic coordinates. Virtual participants are positioned relative to the selected region center using local metre offsets.

The host app needs Android's `INTERNET` permission for tiles and its own server calls. Production apps should set a stable support/contact URL in the tile User-Agent before release and switch to a contracted tile provider if use exceeds the standard OSM service policy.
