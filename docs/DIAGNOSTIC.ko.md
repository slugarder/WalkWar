# WalkWar Debug 사용법

최신 0.3.7(code 10)은 체력 퍼센트를 소수점 둘째 자리까지 표시하고, 모드별 내 기록을 기기 안에 저장합니다. 앱은 기존처럼 별도 패키지 WalkWar Debug로 설치되며 진단 기능과 지정 아이콘을 유지합니다. 일반판과 진단판의 기기 저장소와 플레이어는 서로 분리됩니다.

0.3.5(code 8)는 지정한 지도·칼·WalkWar 로고를 앱 아이콘으로 사용합니다. 일반 앱과 같은 아이콘이며 앱 이름 **WalkWar Debug**로 구별합니다. GPS·걸음·진단 동작은 0.3.4와 같습니다.

`WalkWar-debug.apk`는 JavaScript가 포함된 진단용 APK입니다. PC 서버나 Metro 없이 Railway에 연결합니다. 앱 이름은 **WalkWar Debug**, 패키지는 `com.walkwar.integrated.diagnostic`으로 일반 WalkWar와 함께 설치할 수 있습니다. 별도 설치이므로 참가 이름과 온라인 플레이어 기록도 별도로 시작합니다.

1. APK를 설치하고 이름과 GPS/가상 모드를 선택합니다.
2. 문제가 발생했던 지역에서 확대·축소를 반복합니다.
3. 종료됐다면 **WalkWar Debug**를 다시 실행합니다.
4. 시작 화면의 **진단 기록 보기** → **진단 기록 공유**로 기록을 보냅니다. 플레이 중에는 화면 크기 설정에서도 같은 버튼을 사용할 수 있습니다.

기록에는 기기 모델, Android 버전/API, 앱 버전, 설치된 WebView 공급자·버전, 최근 지도 확대 단계·영역 수·지도 프로세스 종료 이벤트, Android가 보관한 해당 앱의 최근 종료 사유가 포함됩니다. OS가 종료 기록을 남기지 않았거나 해당 OS에서 제공하지 않으면 이유를 확정할 수 없습니다. 위치 좌표·참가 이름·서버 요청 본문은 지도 진단 이벤트에 기록하지 않습니다. 기록은 기기에 보관하고 공유 버튼을 눌렀을 때만 공유합니다.

Android 개발자 도구를 사용하는 경우 USB 디버깅과 Chrome `chrome://inspect`로 진단용 앱의 WebView를 확인할 수 있습니다. 일반 배포 앱에서는 WebView 디버깅을 켜지 않습니다.

## 이번 빌드의 지도 변경

- 표시용 행정 경계를 확대 단계별로 간략화: 전국 응답 기준 2,168,120 → 288,978바이트. 서버의 GPS 판정용 정밀 경계는 변경하지 않았습니다.
- 지도를 움직일 때 같은 국기와 경계를 재사용하고, 이동 중 도착한 갱신은 이동 종료 뒤 적용합니다.
- 지도 영역 요청은 한 번에 하나만 처리하며 중간 화면 요청과 오래된 응답을 버립니다.
- 지도 렌더링 픽셀 비율을 최대 1.5로, 타일 캐시를 소스별 48개로 제한합니다.
- WebView 종료 이벤트를 받으면 지도 재시도 화면을 표시합니다. Android가 앱 전체를 종료하는 모든 경우를 막는다는 의미는 아닙니다.

## GPS 권한과 걸음 batch

### 0.3.4(code 7) 현재 위치 공략과 기여

지도 왼쪽 아래의 **내 위치에서 공략**을 누르면 GPS를 새로 확인하고, 그 좌표가 속한 시·도 / 시·군·구 / 읍·면·동을 찾습니다. 구가 있는 시는 시와 구가 모두 나옵니다. 목록에서 지역을 선택하면 기존 지역 설명 화면으로 이동하고, **공략 시작**을 눌러야 실제 공략이 시작됩니다. 시작할 때도 위치를 다시 측정합니다.

이전 앱은 공략 선택 전에 GPS 전송 순번을 초기화하고 대기 중인 측정값을 버려, 실패 후에도 서버가 다음 위치를 오래된 입력으로 무시할 수 있었습니다. 순번은 새 세션이 확정된 뒤 초기화하며, 위치 전송이 끝난 다음 공략을 요청하도록 수정했습니다. 정지한 상태에서도 위치 갱신을 받을 수 있도록 거리 제한을 없앴습니다. GPS 50m 정확도와 30초 측정 유효시간은 유지합니다. 센서의 원래 측정 시각을 사용하며, 알 수 없는 정확도를 0m로 취급하지 않습니다.

GPS 위치가 자주 갱신될 때 `TYPE_STEP_COUNTER`가 늦게 묶어 보낸 걸음을 짧은 요청 간격만으로 과도한 증가로 판정하던 문제를 수정했습니다. 유효한 지역 내 측정이 이어지면 초당 4걸음의 반영 허용량을 쌓고 최대 120걸음으로 제한합니다. 실제 센서 증가분이 있을 때만 반영하며 위치 불확실·지역 이탈·센서 재시작·30초 초과 공백·일시정지 시에는 기준을 갱신합니다. 첫 센서값은 기준으로만 사용하고 자동 기여는 없습니다. 추적 걸음은 공략 지역 선택과 앱 복귀 때 초기화됩니다.

내 기록은 순위권이 아니어도, 지역 밖이어도, 기여가 0이어도 고정 표시됩니다. 랭킹 상세의 GPS `걸음 확인`은 현재 추적 감지 걸음과 실제 공략 기여를 별도로 표시합니다. 국기는 마지막 점령 당시 1위 팀을 유지하며, 다음 점령이 완료됐을 때 갱신합니다.

현재 위치 찾기는 기존 고정 Railway 지역 조회 API를 사용합니다. 서버 주소 고정, 지도 경량화, 별도 진단 앱은 계속 포함됩니다. API 주소 설정은 변경하지 않았습니다.

에뮬레이터가 서버보다 약 10초 빠른 환경에서 새 GPS가 미래 측정값으로 거부되는 문제도 재현했습니다. 서버 응답 시각과 요청 왕복 시간을 이용해 기기 시계 차이를 보정합니다. GPS가 측정된 후 지난 시간은 유지하므로 오래된 위치를 새 위치처럼 바꾸지 않습니다.

이미 허용된 위치·활동 권한은 조회만 하고 다시 요청하지 않습니다. 미허용 권한 요청은 해당 GPS 세션에서 한 번만 시도합니다. 권한 창 때문에 전경·백그라운드가 바뀌어도 새 센서를 중복으로 시작하지 않으며, 실제 홈 화면으로 나가면 추적을 중지합니다. 복귀할 때 걸음 기준을 새로 잡아 백그라운드 걸음을 합산하지 않습니다.

허용된 권한으로 복귀, 권한 창의 background/active 전환, 권한 확인 중 홈 이동, 거절 후 재요청 반복 방지의 회귀 테스트 4개가 통과했습니다. 진단 기록에는 권한 조회 결과와 GPS 시작·중지·앱 상태 전환도 포함됩니다. 0.3.4 진단 기록에는 `gps-steps`(센서 걸음), callback delta, `gps-result`(서버 처리 결과)도 포함됩니다. 위치 좌표·참가 이름·서버 요청 본문은 기존처럼 기록하지 않습니다.

S22 Ultra/S26 실기기 원인은 아직 확정되지 않았습니다. 이 APK의 기록과 해당 기기 재현 결과로 확인해야 합니다. GPS 현장 걷기 검증도 별도로 필요합니다.

## 확인한 범위

0.3.4 서버 테스트 30개와 모바일 테스트 47개, 타입 검사, 실제 전국 경계 + 메모리 SQLite + HTTP 라우트 GPS 지역 선택 통합 테스트가 통과했습니다. 일반·진단 APK를 빌드하고 Android 16 에뮬레이터에서 설치·실행했습니다. GPS 공략 시작 후 내 기여 0 표시와 감지 0걸음·걸음 센서 사용 불가 표시, `gps-result` 진단 기록을 확인했습니다. Railway의 새 서버 배포 SUCCESS와 기존 게임 기록 보존도 확인했습니다. 기존 고정 Railway, 지도 경량화, 별도 진단 앱은 유지합니다.

Android 16/API 36 에뮬레이터에서 일반 앱과 진단 앱을 점검했습니다. 모의 좌표로 실제 Railway 서버의 현재 위치 목록(부산광역시 → 부산진구 → 부전제1동), 지역 설명, 공략 시작 흐름을 확인했습니다. 에뮬레이터에 걸음 센서가 없고 실제 휴대폰 걷기는 미검증이므로 실제 보행 검증을 뜻하지 않습니다. 새 APK를 설치한 뒤 기기에서 다시 확인해야 합니다.

2026-09-20, Android 16/API 36 에뮬레이터에서 0.3.2-debug를 일반 앱과 함께 설치하고 Metro 없이 실행했습니다. 위치·활동 권한을 각각 허용한 뒤 GPS 추적 상태로 전환됐으며, 홈 화면 이동 후 복귀 시 권한을 다시 요청하지 않았습니다. 에뮬레이터의 걸음 센서 사용 불가 상태는 그대로 표시합니다. 일반 빌드에서는 확대 6→13→6의 14회 조작 동안 같은 앱 프로세스가 유지됐습니다.

진단 앱을 테스트용으로 강제 종료하고 다시 실행한 후에도 이벤트가 남아 있었고, 보고서에 기기·WebView 버전 및 `USER_REQUESTED` 종료 사유가 표시됐습니다. **진단 기록 공유**에서 Android 공유 시트가 열리는 것까지 확인했습니다. 이는 S22/S26에서 발생한 충돌을 재현하거나 해결을 확정한 검증은 아닙니다.

## 개발자 빌드

`mobile/android`에서 `gradlew.bat :app:assembleDiagnostic`을 실행합니다. 결과는 `app/build/outputs/apk/diagnostic/app-diagnostic.apk`입니다. `diagnostic` 변형은 Android 디버깅을 허용하면서 JS 번들을 포함하고 Metro 개발 지원은 비활성화합니다. 보통의 `assembleDebug`는 Metro용이므로 이 배포 파일과 다릅니다.
