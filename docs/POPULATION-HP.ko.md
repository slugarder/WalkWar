# 0.3.6 인구·행정 체급별 몬스터 체력

2026년 8월 행정안전부 주민등록 인구와 게임의 2026-07-01 행정구역 목록을 연결했습니다. 인구 원본은 https://jumin.mois.go.kr/statMonth.do 의 전체읍면동현황, 등록구분 전체이며 외국인은 제외합니다.

## 적용 산식

- 하부: `max(1,000, 인구 × 3)`
- 기초: `14,524,470 + 인구 × 3`
- 광역: `180,815,010 + 인구 × 3`

보정 전 하한은 하부 1,000 / 기초 10,000 / 광역 100,000이며, 각 상위 체급의 최소 HP가 바로 아래 체급 최고 HP의 10배 이상이 되도록 보정합니다. 모든 HP는 반올림 없이 계산합니다. 피해량은 유효 1걸음당 1입니다.

| 지역 | 최대 HP |
|---|---:|
| 부전제1동 | 41,727 |
| 울릉군 | 14,550,711 |
| 수원시 | 18,081,501 |
| 세종특별자치시 | 181,987,224 |
| 경기도 | 222,136,764 |

광역자치단체는 광역, 자치시·군·자치구는 기초, 일반구·제주 행정시·읍·면·동은 하부입니다. 세종의 중간 지도 단계 코드는 광역 세종과 같은 공략 대상으로 처리합니다. 인구 0이며 경계가 없는 5개 지역은 공략 대상에서 제외합니다. 인구 누락을 0으로 채우지 않습니다.

## 진행 기록 전환

기존 고정 720 HP 공략은 이미 가한 피해량을 그대로 유지한 채 새 최대 체력으로 전환합니다. 예를 들어 부전제1동이 700/720이었다면 41,707/41,727이 됩니다. 기여도·걸음·점령 기록·보상·장착 기록을 초기화하지 않습니다.

체력 규칙 버전은 `population-202608-tier10-v1`입니다. 새 체력으로 전환된 공략은 최대 HP와 규칙 버전을 저장합니다. 이후 서버를 재시작하거나 새 인구 자료를 도입해도 진행 중인 공략은 같은 최대 HP를 유지하고, 다음 몬스터부터 새로운 기준을 사용합니다.

전환 직전 상태 전체와 버전은 동일 SQLite의 `migration_backup` 테이블에 `population-hp-v1` 키로 보관합니다. 재시작 시 기존 사본을 덮어쓰지 않습니다.

NPC 자동 피해 등 다른 게임 규칙은 이번 변경에 포함하지 않았습니다. GPS·가상 모드는 같은 HP 산식을 사용하고 진행 기록은 기존처럼 분리됩니다. 서버 주소는 Railway로 고정합니다.

## 데이터 재생성

공식 2026년 8월 CSV를 받은 뒤 다음 명령으로 정적 데이터를 재생성할 수 있습니다.

```powershell
python scripts/import-population.py path/to/mois-population-202608.csv
```

결과는 `server/data/population-balance.json`이며 원본 CSV의 SHA-256과 기준월·보정값을 포함합니다. 서버 시작 시 한 번 읽으며 지도 확대나 GPS 요청마다 인구를 조회하거나 전국 최대값을 재계산하지 않습니다. `Prepare-Railway.ps1`이 배포 묶음에 포함합니다.

## 검증 결과

서버 테스트 38개, 모바일 테스트 47개, 서버 빌드·모바일 타입 검사, 실제 전국 경계 데이터의 GPS 지역 선택 통합 검증이 통과했습니다. 일반·진단 APK는 0.3.6/code 9로 빌드·업데이트 설치했습니다. 일반 앱에서 Railway의 세종 최대 HP 181,987,224 및 현재 체력·기여 표시를 확인했습니다.

Railway 배포 `8857ace8-f0cd-4c6f-acdc-93cdb69361f9`의 SUCCESS, `/health` 규칙 버전, 16개 광역 최대 HP의 계산표 일치를 확인했습니다. 기존 테스트 계정의 20걸음·기여 20·진행도 및 기존 점령 기록을 보존했고, 기존 피해 51이 새 체력에서도 유지되었습니다. 이는 서버/API와 에뮬레이터 검증이며 이번 변경에서 실제 기기 보행을 새로 측정한 것은 아닙니다.
